# STSMN ESP32 firmware (v1.1)

Low-voltage **educational demonstration** only. Never connect it to 230 V mains or a real distribution transformer.
Not certified protection equipment. A qualified adult/technician must review any real installation.

## Files
| Path | What |
|---|---|
| `stsmn_firmware/` | Canonical Arduino sketch folder: `stsmn_firmware.ino` + `config.h`, `util.h`, `risk_engine.h`, `protection_logic.h`, `sensors.h`, `actuators.h`, `secrets.h.example` |
| `stsmn_single/stsmn_single.ino` | The same firmware in ONE file for copy-paste (generated by `python3 tools/make_single_ino.py`) |

## Build (Arduino IDE 2.x)
1. Install **ESP32 by Espressif Systems** (core 2.x or 3.x) in Boards Manager.
2. Library Manager: **OneWire**, **DallasTemperature**.
3. Board: **ESP32 Dev Module** (ESP32 DevKit V1 / WROOM-32). Upload speed 921600 or 115200. Serial Monitor 115200.
4. Multi-file: copy `secrets.h.example` to `secrets.h` in the sketch folder and set a **new** password (8-63 characters).
   The sketch refuses to compile with the public example password. Single-file: edit `WIFI_AP_PASSWORD` near the top.
5. Upload. Phone joins Wi-Fi `STSMN-TR001`, app uses `192.168.4.1`.

## GPS and SMS (new in this version)
* `gps_nmea.h` reads the NEO-6M (only checksum-valid RMC/GGA sentences). A position is reported only while the module has a real fix; no fix for 10 s = `null`, never an old or invented position.
* `sim800.h` + `sms_logic.h`: when the status ENTERS EMERGENCY, one SMS goes to `ALERT_PHONE_NUMBER` (set it in `secrets.h`; the `+91XXXXXXXXXX` placeholder keeps SMS off): `STSMN TR-001 EMERGENCY risk 92/100 temp 71.2C https://maps.google.com/?q=LAT,LNG` (or `GPS: no fix`). At most one per 2 min, reminder every 30 min while the alarm lasts, failed sends are retried. Warning SMS: `SMS_ON_WARNING` in config.h.
* GPS and SIM run in their own low-priority task; they never touch the relay, sensors or the protection task.
* `GET /api/health` additionally returns `gpsFix, gpsSats, lat, lng, gsmReady, gsmRegistered, gsmSignal, smsEnabled, smsSent, smsFailed` (`lat/lng` are `null` without a fix). `/api/status` is unchanged.
* SIM800L is a 2G modem: it needs a 2G network in your area. Beginner wiring guide: `docs/STSMN_Wiring_Guide.pdf`.

## Behaviour that matters
* Protection (sensors, risk score, relay, LEDs, buzzer) runs in its **own FreeRTOS task** (priority 3, core 1) with a task watchdog (8 s). The HTTP server runs in the Arduino loop; a slow/stalled client cannot delay protection. The phone can never arm, disarm or override anything.
* **Relay stays cut at boot** and is only allowed after the 3 s boot check AND all protection sensors (temperature, current, voltage) have been valid for 2 s. EMERGENCY cuts it; a sensor fault lasting 10 s cuts it; both need a fresh stable-valid period to come back.
* Invalid sensors are reported as `null` in JSON, never as 0.
* If the firmware hangs, the watchdog resets the ESP32; the relay pin is then high-impedance until `setup()` runs, so **wire the load through COM + NO** and use a module whose input idles to "off".

## API (read-only, plain HTTP on the WPA2 access point)
`GET /api/status` -> `deviceId, fw, uptime (ms, 64-bit), temperature, voltage, current, smoke, flame, oilLevel, risk, status, relay, alarm, seq`
(`temperature/voltage/current/oilLevel` are numbers or `null` when invalid).
`GET /api/health` -> `deviceId, fw, uptime, seq, clients, mq2Ready, tempValid, currentValid, voltageValid, relayMismatch, armed, heapFree, stackFreeBytes`.
Errors: `404 {"error":"not found"}`, `405` + `Allow: GET` for other methods on these paths, `503` before the first state exists.

## Calibration checklist (values in `config.h` are DEMO assumptions, not verified on your modules)
- [ ] ACS712: idle level at the ADC pin must be 1.2-2.1 V; check `ACS_MV_PER_A` for your variant (5/20/30 A) and the divider ratio.
- [ ] Voltage module: compare with a multimeter, set `VOLT_CAL_FACTOR`; set `NOMINAL_VOLTAGE_V` for your supply.
- [ ] MQ-2: needs 24-48 h burn-in the first time; baseline is taken after 60 s in clean air (smoke present at that moment = wrong baseline).
- [ ] Water level: set `LEVEL_DRY_MV` / `LEVEL_FULL_MV` with the sensor dry and fully wet.
- [ ] Relay polarity (`RELAY_ACTIVE_LOW`) and flame polarity (`FLAME_ACTIVE_LOW`) on your modules.
- [ ] Thresholds (`TEMP_*`, `CURRENT_*`, risk limits) are demo values.
